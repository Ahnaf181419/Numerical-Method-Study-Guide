## 1. What this repo does

A static study site for the Numerical Methods course (CSE 2201). Twelve chapters, each with lessons, worked exam-format examples, flashcards, quizzes and interactive calculators; plus the four past papers with full model answers and a mock exam. Everything runs in the browser — there is no server, no login and no data leaving the device (progress is kept in `localStorage`).

**Load assumed:** one student, one device, one browser tab. Nothing here is multi-user, and no page writes data that another page depends on.

## 3. Findings

### Must fix

**1. The Weddle solver's own default now fails — a regression from yesterday's spacing guard** (`src/lib/solvers.js:28-36`, `src/lib/solverConfigs.js:276`)
- **What this is:** Every equal-interval rule now checks that the x-values are evenly spaced, using a tolerance of one billionth. The Weddle solver ships with x-values `0, 0.333333, 0.666667, 1, 1.333333, 1.666667, 2`, which are six-decimal roundings, so two of the six gaps differ from the first by 0.000001.
- **Problem:** Open Chapter 9 → Solve → "Weddle's rule on a table" and the solver shows **"the x values must be equally spaced for this rule."** instead of the worked example. Verified by running the shipped default through the solver.
- **Fix:** Make the tolerance relative to the step instead of absolute — in `spacing()`, compare `Math.abs(v - xs[i - 1] - h) > Math.abs(h) * 1e-5`. One line; the uneven-data guard still rejects a genuinely uneven table (the test table `[0, 1, 3]` is off by 100%).
- **If we skip it:** One of the five integration calculators is dead on arrival, and it is the one the Weddle past-paper question needs.

**2. The Gauss and Gauss-Jordan solvers open on a mistyped matrix** (`src/lib/solverConfigs.js:14`, `:31`, `:51`)
- **What this is:** The default matrix for the two flagship elimination solvers.
- **Problem:** The default reads `1,1,1;2,3,1;3,4,5` with constants `6,13,18`, but the teacher's board example is $x+y+z=6$, $2x+3y+z=13$, $3x+2y+5z=18$ (`src/data/elimination.js:131`, the solver's own comment says "Defaults are the slide/note examples so each solver opens on a known answer"). The third row should read `3,2,5`. As shipped, the solver answers **x = 5.6667, 0.6667, −0.3333** instead of the promised (3, 2, 1).
- **Fix:** Change `3,4,5` to `3,2,5` in the three default strings. Add a test that the default solves to (3, 2, 1).
- **If we skip it:** The calculator that exists to check the student's own working disagrees with the worked example on the same screen.

**3. The Chapter 6 difference table has two wrong cells** (`src/data/differences.js:175-184`)
- **What this is:** Chapra's example table of $f(x)=x^4$ for $x=-2\ldots4$.
- **Problem:** In the diagonal layout, the second-difference column must read 14, 2, 14, **50**, **110** down the rows. The table prints **110** in the $x=3$ row (where it should be 50) and leaves the $x=4$ cell **empty** (where it should be 110). Everything else in the table is right, and the same chapter shows the correct table earlier at `differences.js:148-156`, so the page contradicts itself.
- **Fix:** Move the 110 one row down and put 50 in its place. Add a guard test that recomputes the table from the y-values.
- **If we skip it:** A student cannot tell which of the two tables is right, and the whole chapter is about building these by hand.

**4. The significant-digits answer is wrong in two places** (`src/data/errors.js:60-64` and the chapter quiz item at `errors.js:754`)
- **What this is:** The check-your-yourself question on "Significant digits" and the same question in the chapter quiz.
- **Problem:** Both mark **3** as correct for $0.0005010$ and explain "the significant digits are 5, 0, 1 — three of them". But the chapter's own rule (`errors.js:320`) counts every zero to the right of a non-zero digit as significant, and the chapter's own table (`errors.js:330`) counts $0.000620$ as **3** (6, 2, 0). By the same rule $0.0005010$ is 5, 0, 1, 0 = **4** significant digits (5.010 × 10⁻⁴). The option "4" is sitting in the list, unmarked.
- **Fix:** Mark "4" correct in both places and rewrite the explanation to name the trailing zero.
- **If we skip it:** The site contradicts its own rule and the standard convention, and the wrong option is the one students are taught.

**5. The spherical-tank example silently loses its good explanation and keeps a wrong one** (`src/data/roots.js:576` and `:581`)
- **What this is:** A worked example (Fall 2023 Q3(b)).
- **Problem:** The object literal has **two `explanation:` keys**. V8 accepts that (last one wins) and drops the first, which is the good two-paragraph version. The version that survives ends with "Here the computed volume is 1047.2 and half the sphere is $1000\pi/3 = 1047.2$, so the answer is right" — numbers from a different problem (a different radius). This question's answer is $h = 2.027$ m with volume **30 m³** ($R = 3$), as the steps themselves state.
- **Fix:** Delete the first `explanation` block and correct the last sentence of the second to the numbers in this example.
- **If we skip it:** The student is told to check their answer against 1047.2 when the answer is 30, and the actual explanation never appears.

**6. Matrix inversion has no lesson** (`src/data/elimination.js` — only two mentions, at `:134` and `:299`)
- **What this is:** A syllabus-adjacent topic: Spring 2024 Q2(c) asks for the matrix-inversion method, and Spring 2024 Q1(d) asks the four scenarios of solution existence.
- **Problem:** Neither determinants/cofactors/adjoints nor the four scenarios are taught anywhere on the site. A zero student meets them for the first time inside a past-paper answer, and the "full answer" tab is the only place they exist. These two questions are worth roughly ten marks.
- **Fix:** One new lesson section (determinant → cofactor matrix → adjoint → inverse → multiply by b) plus one worked example on the Spring 2024 system, one check question, and a solver. The four scenarios are a short table and can share the same section.
- **If we skip it:** The only syllabus-adjacent topic a from-zero student cannot learn from the site.

### Should fix

**7. The search box advertises another course's topics** (`src/components/Search.jsx:65`)
- **What this is:** The placeholder text in the search field.
- **Problem:** It reads "Search lessons and formulas, e.g. Hamming, guard band, Nyquist" — those are data-communication topics left over from a sibling project. Searching them returns nothing on this site.
- **Fix:** Replace with three topics that exist here, e.g. "e.g. Simpson, pivot, Stirling".
- **If we skip it:** The first thing a new student types comes from the wrong course.

**8. Dead CSS from the sibling project** (`src/index.css:258-269`)
- **What this is:** The `.playhead` animation and its `@keyframes sweep`.
- **Problem:** No component uses `playhead` (grep across `src/` finds only the CSS), and the comment above it — "Modulation lab playhead" — belongs to the other course's project.
- **Fix:** Delete the twelve lines.
- **If we skip it:** Dead code that sends the next reader hunting for a modulation lab.

**9. Two math render paths can still white-screen the app** (`src/components/Search.jsx:88`, `src/components/CheatSheet.jsx:61`)
- **What this is:** Yesterday's fix gave `InlineMath`/`BlockMath` a `renderError` handler in `NotesView.jsx` and `Solvers.jsx`.
- **Problem:** The formula sheet and the search results render math without it. A single malformed formula makes KaTeX throw, React unmounts the whole tree, and the student gets a blank page with no way back.
- **Fix:** Pass the exported `mathError` handler at those two call sites.
- **If we skip it:** Low odds today (every formula is compile-tested), but total damage when it happens.

**10. Taylor series is used in three derivations but never introduced** (`src/data/roots.js:295`, `src/data/errors.js:284`, `src/data/differentiation.js:52`, `:86`)
- **What this is:** The Newton-Raphson derivation, error propagation and the truncation-error proof all expand a function in a power series.
- **Problem:** A student starting from zero has never been told what a Taylor series is, so the derivation reads as magic.
- **Fix:** One short "Start here" paragraph with the first two terms of the expansion and a picture of the tangent-line approximation, linked from the three places that use it.
- **If we skip it:** The three proofs that the examiner asks for are the three a beginner cannot follow.

**11. PCA promises a method the site never teaches** (`src/data/pca.js:117`)
- **What this is:** A line promising eigenvalues are "found by Jacobi's method for bigger sets".
- **Problem:** The Jacobi eigenvalue algorithm exists in the solver engine (`solvers.js:833`) but no lesson explains it. The promise leads nowhere.
- **Fix:** Either teach it in one section (the engine already does the work) or drop the promise from the sentence.
- **If we skip it:** One sentence points a student at a hole in the site.

**12. The mock exam is multiple-choice only** (`src/components/ExamPrep.jsx:67-129`)
- **What this is:** The 10/20/40-question mock drawn round-robin from all twelve chapters.
- **Problem:** It never asks for a written script, so the six-mark exam habit (marks per step, pivot check, no back-substitution) is only practised in the Past papers tab.
- **Fix:** Optional: add a "write the answer, then compare" mode that shows a solved script for one numerical question per chapter.
- **If we skip it:** The student has never written a full answer under time pressure.

**13. The teacher's exact drill examples are not reproduced** (informational)
- **What this is:** The sheet lists book examples (4.4–4.8, 6.3–6.5, 7.1–7.3, 9.1–9.3, 10.1–10.2, 11.1–11.4).
- **Problem:** Every **method** is taught, but with past-paper or equivalent examples instead of the book's numbered ones.
- **Fix:** None needed for the exam — a note in `docs/EXAM-GUIDELINES.md` already lists the substitutions. Worth remembering that the book is still needed for those drill numbers.
- **If we skip it:** No marks lost, but the student may meet a book's exact numbers for the first time in the exam.

### Nice to have

**14. Two chapters have no interactive calculator** (deviation from the content rules, documented at `src/lib/audit.test.js:183-194`)
- **What this is:** Errors & Approximations and Finite Differences have hand-verified numeric examples but no solver; `diffTable` exists but is only linked to Chapter 8.
- **Fix:** Link the difference-table solver to Chapter 6 as well; add a small chopping/rounding calculator if wanted.
- **If we skip it:** Already a documented, deliberate deviation.

**15. PCA steps list only the first two eigenvalues** (`src/lib/solvers.js:899`)
- **What this is:** The eigenvalue/eigenvector steps are hard-coded to two components.
- **Problem:** Three-column input (allowed by the parser) would print an incomplete eigen block — no wrong numbers, just missing ones.
- **Fix:** Loop over `eigvals.length` instead of naming two.
- **If we skip it:** The solver is labelled "x,y", so it only bites someone who ignores the label.
